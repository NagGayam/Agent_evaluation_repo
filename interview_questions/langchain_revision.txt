1. What is LangGraph? What problems does it solve?
- LangGraph is a graph-based orchestration framework designed to build stateful, complex AI agents. 
- It solves challenges such as managing agent state, controlling execution flow, handling cyclic workflows,
- recovering from failures, and integrating human approval into agent execution. It is particularly useful 
- for building reliable, long-running AI agent applications.
- LangGraph controls the boundaries and execution flow, while the AI agent can make decisions within those boundaries.
- The final point is we will create the workflow with langgraph and agent can make its own decisions in that workflow

3. Explain the architecture of a LangGraph workflow?
- LangGraph follows a graph-based, stateful execution architecture.
- A workflow consists of nodes connected by edges, with shared state carrying information between execution steps.
- main components of langgraph are :
- state : State is the shared data maintained throughout workflow execution.
- nodes : Nodes are python functions that performs specific operations
-edges : Edges determines which node to execute next 
-edges are two types i) normal edge , ii)conditional edge 
-START and END : entry and endpoints of the workflow
-Checkpointer : A checkpointer saves graph execution state, enabling persistence, recovery, and resuming interrupted workflows.

13.  How do you create a synchronization point after
    parallel node execution?
- Buddy, in LangGraph, we create a synchronization point (fan-in) using add_edge() with a list of source nodes. 
graph.add_edge(START, "A")

# Parallel execution (fan-out)
graph.add_edge("A", "B")
graph.add_edge("A", "C")

# Synchronization point (fan-in)
graph.add_edge(["B", "C"], "D")

graph.add_edge("D", END)

16. What is checkpointing in LangGraph? 
- Buddy, checkpointing in LangGraph is a mechanism that saves the graph's state and execution progress so the workflow can be resumed later.
-Why is checkpointing needed?
- Failure recovery: Resume from a saved checkpoint after an interruption.
- Human-in-the-loop: Pause execution for human approval and resume afterward.
- Conversation memory: Preserve state across multiple interactions.
- Debugging: Inspect previous states and execution history.

22.What happens when a node resumes after an interrupt? 
- When a node resumes after an interrupt, LangGraph re-executes the interrupted node from its beginning. The interrupt() function returns the supplied resume value, allowing the remaining code to execute normally. Previously completed nodes are not re-executed as part of normal resumption.

26 . What is the difference between invoke() and stream()? 
- invoke() executes the graph and returns its final output, whereas stream() provides incremental execution updates, enabling real-time monitoring, debugging, and progress tracking.
- From an AI SDET perspective: stream() is particularly useful for validating intermediate node outputs, state transitions, and agent execution paths rather than testing only the final response.
**********************************************************************
27 .explain the streaming modes in langgraph ?
- LangGraph provides five commonly used streaming modes that allow us to monitor graph execution in real time:

- **updates:** Streams only the state updates returned by individual nodes.
- **values:** Streams the complete graph state after each superstep.
- **messages:** Streams LLM-generated message chunks along with their metadata.
- **custom:** Streams developer-defined events or progress messages using `get_stream_writer()`.
- **debug:** Streams detailed execution information, including node execution events, state and checkpoint information.

These streaming modes are useful for real-time monitoring, debugging, tracking state transitions, and validating intermediate agent behaviour without waiting for the entire workflow to complete.

LangGraph also supports using multiple streaming modes simultaneously.
*********************************************************************
 28 .  How would you debug a failed node and inspect its
    input, output and state?
- To debug a failed node in LangGraph, I would use streaming, checkpointing, and tracing.
- stream_mode="debug": Inspect detailed node execution events and identify where the failure occurred.
- stream_mode="updates": Inspect individual node outputs and state updates.
- get_state(): Retrieve the latest checkpointed graph state.
- get_state_history(): Inspect previous state snapshots to understand what state was available before the failure.
- LangSmith or Langfuse: Inspect detailed node inputs, outputs, LLM calls, tool calls, and exceptions when tracing is configured.
- Time travel: Replay execution from a previous checkpoint to reproduce and investigate the failure.
